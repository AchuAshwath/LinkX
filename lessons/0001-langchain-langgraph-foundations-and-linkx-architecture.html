Lesson 0001

LangChain & LangGraph Foundations for LinkX

How stateful graphs, rich input payloads, and modular tools replace brittle automation scripts.

🎯 The Core Mission

Transition LinkX from running hardcoded, disconnected automation scripts into an orchestrated, reusable, and self-healing agentic system.

1. The Mental Model: LangChain vs. LangGraph

Many developers confuse LangChain and LangGraph. Here is the clean boundary:

Component What it Does LinkX Example
LangChain Building blocks: Model wrappers, typed structured output (with_structured_output), and @tool definitions. get_chat_model(), ExtractedTrendingTopic schema, @tool def take_screenshot().
LangGraph The orchestration engine. Controls state, loops, conditional decisions (if/else), retries, and multi-step agent flows. Self-healing supervisor that detects selector misses, diagnoses DOM, hot-patches JSON, and retries.

2. Does LangGraph Only Accept Text as Input?

💡 The Answer: No! LangGraph receives Rich Typed State

A LangGraph workflow does not operate solely on text strings. Every graph is initialized with a Typed State schema (a Pydantic model or TypedDict). The input can be any structured payload you want.

For example, when a user clicks the "Draft" button near a scraped topic in the LinkX UI, the frontend doesn't just send text. It sends a structured request that populates the Graph's State:

# The State schema shared across all nodes in the Graph
class CurationState(TypedDict):
    user_id: str
    topic_title: str
    topic_url: str | None
    scraped_tweets: list[dict]
    screenshot_b64: str | None
    detected_insights: list[str]
    linkedin_draft: str | None
    x_draft: str | None
    status: str

# Invoking the graph from FastAPI with rich structured data:
initial_state = {
    "user_id": current_user.id,
    "topic_title": "Autonomous AI Agents",
    "topic_url": "https://x.com/search?q=AI",
    "scraped_tweets": topic.tweets,
    "screenshot_b64": None,
    "status": "pending",
}

# The graph receives this full object at START
result = await curation_graph.ainvoke(initial_state)

This means your frontend components and buttons have full context awareness — they can trigger the graph with topic IDs, user preferences, tone flags, or image attachments.

3. Turning Automation Scripts into Modular Tools

Previously, LinkX had standalone scripts like scrape_trending_topics.py and x_posts.py. In an agentic architecture, we convert these into modular tools that either:

  1. Run as deterministic graph nodes (e.g. ScrapeNode).
  2. Are callable by an LLM reasoning agent via LangChain's @tool decorator.
from langchain_core.tools import tool

@tool
async def scrape_trending_topics_tool(max_topics: int = 3) -> list[dict]:
    """Scrapes top trending topics from X using stealth Playwright automation."""
    result = await scrape_trending_topics(max_topics=max_topics)
    return [t.model_dump() for t in result.topics]

@tool
async def test_selector_tool(selector: str) -> dict:
    """Tests if a candidate CSS selector exists and is visible on the current page."""
    return await test_selector_candidate(page, selector=selector)

@tool
async def patch_config_tool(config_key: str, new_selector: str) -> bool:
    """Updates scrape_config.json or x_selectors.json with a verified working selector."""
    return patch_selector_config(key_path=config_key, new_selector=new_selector)

4. The Self-Healing State Graph

Here is how LangGraph handles cycles (loops with exit conditions) to achieve self-healing:

[START] │ ▼ [Execute Action Node] ──(Check Selector)──► [Selector Valid?] │ ┌────────────────────────────────┴────────────────────────────────┐ ▼ ▼ [Yes: Success] [No: Element Miss] │ │ ▼ ▼ [END] [Diagnose Failure Node] (Captures Screenshot + DOM) │ ▼ [Verify Candidates Node] (Tests selectors on live page) │ ▼ [Patch Config Node] (Updates JSON file) │ ▼ (Loop back to Execute Node)
